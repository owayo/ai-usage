# 保守レビュー記録

2026年10月の依存更新とコードレビューで確認した不具合。ソース全体を AST で調査し、再現できる不具合と、コードから誤動作を断定できる箇所を修正した。複雑さだけを理由とするリファクタリングは行っていない。

## 確認できた不具合

| 対象・再現条件 | 不具合と断定できる根拠 | 修正と回帰テスト |
|---|---|---|
| キャッシュに複数プロバイダを保存し、`--statusline --input <PATH> --only codex` を実行 | キャッシュ経路は `--only` を読まず全アカウントを描画していた。取得直後の描画と同じ指定で結果が異なる | 描画前に対象プロバイダだけ残す。実際の CLI で単一プロバイダ、非表示設定との併用、未指定の3ケースを検証 |
| statusline のラベルに `👩‍🔬`、家族絵文字、国旗、結合文字を使う | 文字単位の幅の合計は、表示幅2桁の絵文字列を過大評価する。途中で切ると絵文字そのものが変わり、後続列も揃わない | 文字列全体の表示幅で判断し、書記素境界でのみ短縮。絵文字列と境界、結合文字の回帰テスト |
| Grok 認証情報に同じ秒の `.100` と `.900` に作成された完全なエントリがある | Unix 秒へ変換していたため両者が同値になり、キー順によって古い認証情報を選んでいた | 小数秒を保持する日時を比較。古いエントリが先に並んでも新しい方を選ぶテスト |
| 端末で通常テーブルに `--no-color`、空でない `NO_COLOR`、または `TERM=dumb` を指定 | 色の有効判定は statusline にしか渡されず、テーブルのサービス、利用枠、エラー、アクティブ行は無条件で着色されていた | 共通の判定をテーブルにも渡す。TTY に依存しない強制描画で全セルの ANSI 有無を検証 |
| Antigravity の探索で `ps` / `lsof` が応答しない | 同期 `.output()` が async の実行スレッドを塞ぐため、外側の非同期 timeout ではその呼び出しを中断できない。探索が終わるまで OAuth フォールバックにも進めない | 非同期プロセス実行、1秒の個別期限、キャンセル時の終了を導入。成功・終了失敗・起動失敗、および30秒の sleep を短い期限で打ち切るテスト |
| `--init-config --config ./alternate.toml` を実行。または存在確認後に別プロセスが出力先を作成 | 指定パスを無視して既定パスへ書いていた。また `exists()` と `write()` の間に作成されたファイルは上書きされ、リンク先が存在しないシンボリックリンクも追跡して書き込んでいた | 指定先を使い、`create_new(true)` で排他的に新規作成。既存時は stdout に雛形を出す。実 CLI で指定先・親ディレクトリ・既存内容とリンクの保持を検証 |
| Chrome 表示名が重複し、生成設定や手書き設定にも同じ表示名が複数ある | 各設定行が同じ先頭プロファイルに一致し、別プロファイルを取得できず、同じプロバイダへ同じ Cookie で並列フェッチしていた | 未使用の一致ディレクトリを優先し、ディレクトリ・プロバイダ単位で重複を除外。別プロバイダの設定とラベルは保持。雛形には一意なディレクトリ名を使う。同名・重複設定・名前衝突・プロバイダ別設定を検証 |

修正は `src/main.rs`、`src/render/statusline.rs`、`src/render/table.rs`、`src/grok.rs`、`src/antigravity.rs` と、その単体テストおよび `tests/statusline_cache.rs` にある。キャッシュ絞り込み、絵文字幅、Grok の小数秒順序は、修正前に回帰テストの失敗も確認した。

## 依存とビルド環境

`depup --install --include-pinned` で clap を 4.6.7、toml を 1.1.6 に更新した。依存ライブラリのメジャー更新はなかった。書記素の判定には既に間接依存していた unicode-segmentation 1.13.3 を直接依存に追加し、非同期探索用に Tokio の `process` 機能を有効にした。

CMake も `mise.toml` で管理し、depup で 4.4.3 に更新した。`make setup` と CI は同じ固定版を使う。Rust は既存の 1.98.1 を維持した。

## 未確定の指摘

トークンを保存せず refresh する運用の長期的な影響、OAuth の HTTP 400 に対する再ログイン案内、端末制御文字を含むラベルや API エラーの扱い、将来のキャッシュ周期値への互換性は、外部仕様や想定入力の追加確認が必要であり変更していない。Cloudflare 本文判定と OAuth クライアント情報の抽出も、具体的な誤判定・誤抽出の再現がないため変更していない。

## 検証

`make ci` で rustfmt、clippy (`-D warnings`)、単体テスト183件、CLI テスト5件が成功した。`cargo audit` は242依存に対して脆弱性なし。wreq が system-configuration 0.7.0 を使うことも確認した。`make build` と実アカウントで Claude / Codex の API 取得も成功した。他のプロバイダの実通信には認証情報やローカル環境の準備が必要であり、全プロバイダの成功を保証する検証ではない。個人情報を含む実行結果は公開文書へ転記していない。

actionlint 1.7.12 の実行では `actions/create-github-app-token@v3` の入力定義に古い判定が残り、`client-id` を誤って拒否した。[公式の action.yml](https://github.com/actions/create-github-app-token/blob/v3/action.yml) は `client-id` を受け付け、`app-id` は非推奨かつ必須ではない。この2件だけを実行引数で除外した再検査は成功し、ワークフローや検査設定へ恒久的な除外は追加していない。
